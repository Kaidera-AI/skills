# Gem qualification tasks — required, not yet executed

The runtime operator and creative owner run these against the approved installed pack on the exact target. Source checks cannot substitute for these outputs. Use only synthetic content and a supplied test brand with licensed logo/fonts; no customer data or generation spend is required.

| Task | Selection / required evidence | Expected failure case |
|---|---|---|
| Static social proof card with exact heading, three numbers and canonical test logo | visual-design-production; editable composition plus requested-size export/hash, actual thumbnail/full-size inspection and exact-copy check | Missing logo returns a dependency hold, never a generated mark. |
| Six-second deterministic loop or supplied 3D scene proof | motion-3d-production plus installed selected renderer workflow; source/settings, exported duration/fps/dimensions/hash and actual playback/keyframe inspection | Missing renderer returns a precise capability hold without an install or paid API call. |
| Three-slide deck: claim, evidence comparison, closing | presentation-design plus installed presentation format workflow; editable deck, PDF if requested, every-slide rendered QA, source/hash/rights manifest | Manual source edit is preserved in the next revision; absent PDF converter is reported rather than claiming PDF equivalence. |
| Existing interface polish/audit request | design-selection → existing ui-design-engineering or ui-ux-review, depending on action | An exported animation request is routed to video production, not assumed to be UI motion. |
| Approved existing asset with a broken pointer | inspect/repair receipt only | No new generation or replacement without a revision instruction. |
| Project-transfer boot | agent-skill-onboarding; effective project/profile/persona/task/SOP/skill lock, binding readback and returned evidence | Wrong-project identity or held skill blocks readiness; a copied file is never marked active. |

Reviewers record each task as unverified/pass/fail/held, actual artifact hashes, tools/versions, findings and creative-owner decision. A hash change after approval reopens affected review. A task not relevant to the current role assignment stays explicitly not-required with the owner's reason; it is not falsely passed.
