# Investor lead generation and outreach

Use this skill when a company raising a pre-seed or seed round wants an agent to find investors, write to them one by one, follow up once, pass every reply to the people who take the meetings, and learn from each answer. It is written for any company and any brand. Everything that belongs to one raise (the round, the deck, the owners, the sender, the figures, the exclusions) lives in an instance file built from [the instance template](#file-references-instance-template-md), never in this skill.

The skill grants no authority. Sending email, writing to a CRM, paying for enrichment, submitting a pitch form and anything said in a founder's name each need the authority the instance file names. A researched, scored or approved batch is not permission to send a different batch.

## The loop

1. **Brief.** Read the instance file: round and deck, who releases names, who approves copy, who takes meetings, sender, copy rules, figure tiers, regions and exclusions. Ask only for what is missing.
2. **Research** ([research](#file-references-research-md)). Funds first, then the decision makers at each fund from its own team page. Record the fund's own words on thesis, stage and minimum cheque, check its portfolio for competitors, find its pitch form, and write one plain opening line per person.
3. **Record** ([database](#file-references-database-md)). Every fund, person, evidence row, release, touch, outcome and meeting goes into the investor database under a stable id. A CRM may be the system of record for stages; the database is the portable copy that outlives any one CRM and feeds the learning loop.
4. **Release.** One list per research turn to the release owner, naming every person to be written to with role, fund, figure, send day and the exact opening line they will read. Record the yes by lead id with the owner's message reference. A name the owner strikes stays out.
5. **Send** ([outreach strategy](#file-references-outreach-strategy-md)). One email per person, in the investor's own morning, with the deck built for that investor attached. One follow-up, then stop.
6. **Replies.** Any reply from anyone at the fund stops every sequence there. Answer within the hour with the standard reply the owners approved, then hand the thread to them. Pitch forms, documents and terms are the owners' to decide.
7. **Learn** ([learnings](#file-references-learnings-md), [weekly refresh](#file-references-weekly-refresh-md)). Every reply, pass, bounce and owner correction becomes a dated learning with its evidence and the rule it changes. Once a week rebuild the database, update the learnings, ingest both into the team's memory store and republish the generic edition of this skill.

## Stop conditions

- A kill switch file or flag the instance names stops every send and follow-up. Set it before anything else when an owner gives a new rule, because a scheduled sender keeps firing while you work.
- Hold one lead, not the run, for a missing minimum, a missing release, an unverified address or any hold reason.
- Hold the ramp if hard bounces pass 3% or any spam complaint arrives.
- Stop and ask when a step would send as a founder, change a round figure above the instance ceiling, spend money or contact a private individual.

## What to report

Count by fund, because the fund is what answers: people and funds written to, funds that replied by hand, funds that declined or opted out, and funds with a meeting on the calendar. An automatic out-of-office notice is not a reply, a booking link sent is not a meeting, and a meeting is not an investment. Say when each figure was counted and from which record.

## What never leaves the instance

Investor names, addresses, notes, message references, round terms and the owners' words stay in the instance's own storage. The generic edition of this skill carries methods and anonymised lessons only; see the publishing check in [weekly refresh](#file-references-weekly-refresh-md).

# The investor database

The investor database is the portable record of a raise: who was researched, why, what they were sent, what they said and what the team learned. It is rebuilt from the outreach records, so it can be thrown away and rebuilt at any time, loaded into any CRM, and carried into the next round or the next company.

Keep it in the instance's private storage. It holds names, addresses and notes about people, so it never goes into a public repository or a shared skill.

## Schema

SQLite works everywhere and needs no server. One row per fund, per person, per evidence item, per touch, per outcome and per meeting, plus the learning log:

```sql
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);

CREATE TABLE funds (
  fund_id TEXT PRIMARY KEY,          -- the fund's website domain
  name TEXT NOT NULL,
  investor_type TEXT,                -- VC_FUND, CVC, ANGEL_NETWORK, ANGEL, FAMILY_OFFICE
  region TEXT,
  based_in TEXT,
  thesis TEXT,                       -- in the fund's own words
  stage_fit TEXT,
  min_cheque_amount REAL,            -- as published
  min_cheque_currency TEXT,
  min_cheque_base REAL,              -- converted to the instance base currency
  min_cheque_source TEXT,            -- the page it was read on
  min_cheque_note TEXT,
  conflict_note TEXT,                -- competitor backers and other holds
  pitch_route TEXT,                  -- form, email or network submission
  people INTEGER,
  people_contacted INTEGER,
  outcome TEXT,                      -- best status reached by anyone at the fund
  first_researched TEXT,
  last_touch TEXT
);

CREATE TABLE people (
  lead_id TEXT PRIMARY KEY,          -- fund domain + name slug
  fund_id TEXT REFERENCES funds(fund_id),
  name TEXT NOT NULL,
  role TEXT,
  profile_url TEXT,
  email TEXT,                        -- only a verified address
  email_status TEXT,
  email_domain_agrees INTEGER,
  batch_id TEXT,
  researched_at TEXT,
  priority INTEGER,
  qualification TEXT,
  opening_line TEXT,
  deck_figure TEXT,                  -- the round figure their deck carried
  test_arm TEXT,                     -- A/B half, if any
  released_by TEXT,
  released_at TEXT,
  hold_reason TEXT,
  status TEXT NOT NULL               -- see the status vocabulary
);

CREATE TABLE evidence (
  lead_id TEXT REFERENCES people(lead_id),
  claim TEXT,
  source_url TEXT,
  retrieved_at TEXT,
  label TEXT                         -- observed, provider-asserted or inferred
);

CREATE TABLE touches (
  lead_id TEXT REFERENCES people(lead_id),
  step INTEGER,                      -- 1 first email, 2 follow-up
  sent_at TEXT,
  to_address TEXT,
  message_ref TEXT,
  kept_copy TEXT                     -- path to the email as sent
);

CREATE TABLE outcomes (
  lead_id TEXT REFERENCES people(lead_id),
  at TEXT,
  kind TEXT,                         -- replied, colleague_replied, declined, opted_out, bounced, closed
  detail TEXT,
  message_ref TEXT
);

CREATE TABLE meetings (
  thread_ref TEXT,
  lead_id TEXT REFERENCES people(lead_id),
  state TEXT,                        -- booked, held, closed
  starts_at TEXT,
  detected_at TEXT,
  note TEXT
);

CREATE TABLE learnings (
  learning_id TEXT PRIMARY KEY,      -- L01, L02 ...
  learned_on TEXT,
  title TEXT,
  observed TEXT,
  rule TEXT,
  evidence TEXT,
  generic INTEGER                    -- 1 when the lesson is safe to publish without names
);
```

## Status vocabulary

A person's status is the furthest point their record proves, never an inference:

| Status | Proved by |
|---|---|
| `researched` | A record with evidence |
| `no_address` | Research done, no verified address |
| `held` | A hold reason on the record |
| `released` | The release owner's yes, by lead id |
| `contacted` | Email 1 sent and kept |
| `followed_up` | Email 2 sent and kept |
| `colleague_replied` | Someone else at the fund replied; this person was stopped |
| `replied` | This person, or the fund's team on their thread, wrote back by hand |
| `meeting` | A call with someone at the fund is on the calendar |
| `declined` | The fund said no |
| `opted_out` | The person or the fund asked not to be contacted |
| `closed` | The conversation ended for another recorded reason |

A fund's outcome is the furthest status any of its people reached, with `declined` and `opted_out` taking precedence over `replied`.

## Rebuilding

Rebuild from the outreach records (lead files, the sequence ledger, releases, meetings and kept copies) and, where available, the CRM's stages. A rebuild replaces the file; nothing is edited by hand. Write a small stats file next to it (funds, people, contacted, replied, declined, meetings, learnings) so a weekly report can quote it without opening the database.

## Using it in the next raise

Before researching a new round, load the last database: funds that declined and why, funds whose minimum sat above the round, funds that asked for a form, and people who opted out (who stay out). A fund that declined one round may fit the next; a person who opted out does not.

## Bundled file: references/learnings.md

# Learnings

Anonymised lessons from running this skill on a real pre-seed raise. Each one names what happened, the rule it produced and how to check the rule holds. The instance keeps the full log with names, dates and message references; only lessons that read true without them are copied here. Add new ones at the end with the next number.

**First-week benchmark (one raise, October 2026):** 42 people at 33 funds written to over three sending days; 3 funds replied by hand (about 9% of funds), 2 of them on the day of the email and 1 the next day; 2 of the 3 replies sent the company to a pitch form; 1 meeting booked; 0 hard bounces; 0 opt-outs. Treat this as one data point, not a norm.

**At the first pause (same raise, four sending days):** 62 people at 50 funds written to; 5 funds replied by hand (10% of funds), 3 of them sending the company to a pitch form; 2 passed (one on stage, one at its form screen); 1 meeting booked; 0 hard bounces; 0 opt-outs; no follow-up sent yet.

**At the second pause (same raise, about three weeks of sending):** 137 people at 80 funds written to; 11 funds replied by hand (about 14% of funds); 7 passed, several because the company was too early for them; 2 funds reached a meeting as the database counts it; 15 follow-ups sent. The founder's own network added funds outside the sequence that this count leaves out.

### L01 · 2026-10-05 · Match the deck's round figure to each fund's minimum
- **Observed:** A deck stating a raise below a fund's published minimum cheque tells the fund the round is not for them before they read on.
- **Rule:** The deck carries the lowest of a few round tiers that covers the fund's minimum, in the fund's currency. The email body never states a figure.
- **Check:** Open the attached PDF of a sample of sent emails and compare the figure with each fund's recorded minimum.

### L02 · 2026-10-07 · Read the minimum on the fund's own site before the first email
- **Observed:** A press figure understated one fund's minimum, and another fund's own manifesto overturned a tracker figure. Both had already been written to.
- **Rule:** No first email until the minimum, or its absence, is read on the fund's own site. A press figure needs an owner's named exception.
- **Check:** Every first email's lead record has a minimum source on the fund's own domain or a recorded exception.

### L03 · 2026-10-05 · Many funds want their pitch form, not email
- **Observed:** Two of the first three human replies came within a day and redirected the company to the fund's pitch form.
- **Rule:** Find the form during research. Form funds go on the release list as form submissions, drafted for an owner to submit.
- **Check:** The fund record has a pitch route before release.

### L04 · 2026-10-05 · Replies come from team addresses
- **Observed:** A fund replied from a shared team address with the partner copied, not from the partner written to.
- **Rule:** Any address at the fund's domain counts as a reply and stops every sequence at that fund.
- **Check:** The reply watcher matches on domain, and colleagues show as stopped after a reply.

### L05 · 2026-10-07 · Check each portfolio for competitors before release
- **Observed:** Four funds in early batches backed direct competitors. One of them later declined after a form submission.
- **Rule:** Keep a competitor and backer list; a match holds the lead for the owners before release.
- **Check:** Every batch's release list states that the competitor check ran.

### L06 · 2026-10-08 · Say where the company is based
- **Observed:** A Europe-only fund passed on geography after reading the company as based in another region; the email named customers abroad and only the footer gave the registered office.
- **Rule:** Email 1 says where the company is based in its first sentence about the company.
- **Check:** The copy version carries the location line in every variant of email 1.

### L07 · 2026-10-07 · Write like a person and retire repeated openers
- **Observed:** Two sentence patterns opened about four in ten researched lines in the first 74, and the founder asked for plainer, more human wording.
- **Rule:** One plain fact, said as a person would, then stop. Count patterns per batch and retire any that recurs.
- **Check:** A per-batch count of repeated opening constructions.

### L08 · 2026-10-08 · The founder comes first
- **Observed:** A fund's published guide says early-stage investors weigh the founders first and read the deck, the website and the founder's professional profile together; the founder was on the second-to-last slide and titles differed between deck, email and profile.
- **Rule:** Founder on slide two; one title used everywhere and matching the founder's public profile; nothing on a slide that the profile contradicts.
- **Check:** Compare deck, email signature, website and profile titles before a deck version is pinned.

### L09 · 2026-10-08 · People may not realise an agent wrote to them
- **Observed:** The founder noticed that investors replying seemed unaware they were writing to an AI agent.
- **Rule:** Decide disclosure deliberately. Test a one-line disclosure against none, fund by fund, and report replies and meetings per half. Always answer honestly when asked.
- **Check:** Each fund's record carries its test half from its first email onwards.

### L10 · 2026-10-04 · Verification providers score mailboxes, not employers
- **Observed:** Several partners came back with valid addresses at portfolio companies or universities. The second named partner at the same fund resolved every case.
- **Rule:** Require the address domain to agree with the fund; list the fund's alias domains before any paid reveal; on a wrong employer, move to the next partner.
- **Check:** No sent email went to a domain outside the fund's recorded domains.

### L11 · 2026-10-07 · Count from the ledger, not the mailbox
- **Observed:** A reply sat in the mailbox trash and was invisible to search.
- **Rule:** Count replies and meetings from the sequence ledger and the calendar; use mailbox search only as a cross-check, including trash.
- **Check:** The daily status figures reconcile with the ledger.

### L12 · 2026-10-07 · CRM rate limits drop writes silently
- **Observed:** A CRM's rate limit dropped the first activity on one record mid-batch; the re-run updated the record and never added the activity.
- **Rule:** Pace CRM writes below the limit, then read back every record and its first activity.
- **Check:** After each batch, every record has its research activity.

### L13 · 2026-10-05 · Stop the sender before changing a rule
- **Observed:** An owner's new rule arrived 51 seconds after a scheduled send went out under the old one.
- **Rule:** Set the kill switch first, change code and config, dry-run on one real lead, then lift it.
- **Check:** The kill switch history shows a set and a lift around every rule change.

### L14 · 2026-10-07 · One follow-up is enough
- **Observed:** The owners' advisers capped reminders at one, one to two weeks after the first email.
- **Rule:** One follow-up seven business days after email 1, then stop.
- **Check:** No lead has more than two steps sent.

### L15 · 2026-10-08 · Use round figures in the investor's currency
- **Observed:** A minimum converted between currencies produced a figure with two decimals, which an owner read as a mistake.
- **Rule:** Use the tier figures only, in the currency the instance sets for the fund's region; never two decimals.
- **Check:** The PDF builder refuses a figure with two decimals.

### L16 · 2026-10-05 · Attach the deck built for the investor
- **Observed:** A hosted deck link showed one fixed figure to every fund.
- **Rule:** Attach the per-investor PDF; no hosted link with a fixed figure; keep each email as sent.
- **Check:** Every kept copy has the PDF attached and no hosted link.

### L17 · 2026-10-05 · Spell product names in full
- **Observed:** A product abbreviation collided with a term every investor uses for market size.
- **Rule:** Spell product names in full in every investor email and deck.
- **Check:** A copy check refuses the bare abbreviation.

### L18 · 2026-10-07 · One release list per turn, every name listed
- **Observed:** The owners wanted one or two approval emails a day, each naming every person to be contacted.
- **Rule:** One release list per research turn to one named release owner, with each person's role, fund, figure, send day and opening line.
- **Check:** Every sent lead maps to a release with the owner's message reference.

### L19 · 2026-10-08 · A small round can look below a fund's usual cheque
- **Observed:** A fund with a low published minimum wrote an average cheque about seven times larger and preferred to lead.
- **Rule:** Record the average cheque and lead preference; let the owners decide whether to match the average for funds that lead.
- **Check:** Fund records carry the average cheque where published.

### L20 · 2026-10-08 · Declines can land outside your thread
- **Observed:** A fund's form system sent its decline to the founder's own address, not the outreach thread.
- **Rule:** When an owner forwards a decline, close the fund by hand everywhere: CRM, register, meeting reminders.
- **Check:** No reminder is scheduled for a fund marked declined.

### L21 · 2026-10-05 · No codes in subject lines
- **Observed:** An internal programme code in a subject line read as machine-made.
- **Rule:** Subjects in plain words, no codes or batch labels.
- **Check:** A copy check refuses known internal codes in subjects.

### L22 · 2026-10-08 · A new copy version needs a rule for funds already written to
- **Observed:** Switching to a new copy version mid-campaign would have sent a new colleague at an already-contacted fund different wording from the rest of the fund's thread. A no-send preview of the next real send caught it.
- **Rule:** Before switching a copy version or a test on, preview the next real send for each kind of lead: a new fund, a new colleague at a contacted fund, and a follow-up.
- **Check:** The switch-on record lists one previewed email per kind of lead.

### L23 · 2026-10-09 · Funds researched before a rule changed still hold one person
- **Observed:** Two funds researched before the rule to find three to five people per fund each held one person. The only person at one of them had opted out at the enrichment provider, so that fund was never written to.
- **Rule:** Each research turn, check the region's funds from earlier batches for colleagues to add. A colleague at a fund already written to gets that fund's existing email version, framing and pinned figure. Allow the fund's domain by name; never switch the earlier-batch check off.
- **Check:** Every researched fund holds the number of people the current rule asks for, or a recorded reason why not.

### L24 · 2026-10-09 · A search summary can upgrade "ties" to "backed by"
- **Observed:** A search summary said a fund was backed by a large consultancy and named a board member. The article itself said only that the fund had ties to the consultancy, and cut off before any name. A draft release note had repeated the summary.
- **Rule:** Any fact about a fund that is not on its own site is read in the source itself, with its date, before it goes in a release note. A search summary is a lead to a source, never the source.
- **Check:** Every outside fact in a release note has a link and a date, and the source says it in those words.

### L25 · 2026-10-09 · Size the turn against the day it will send on
- **Observed:** A research turn had eight ready names, but its send day held only nine first emails against a daily cap of 20. Adding a third partner at a fund already researched took the day to ten.
- **Rule:** Run the release simulation before writing the list. If the send day sits well under the cap, add people at funds already researched before reaching for new funds.
- **Check:** Each release list states the send day's planned count against the cap.

### L26 · 2026-10-10 · A fund can reply from a second domain
- **Observed:** A partner answered from a second company domain, through an email assistant, the morning after the first email. The reply watcher searched only the domain written to, so the follow-up stayed due until it was stopped by hand.
- **Rule:** Record every domain a fund's people mail from. Also match replies on your own Message-ID in the reply's References or In-Reply-To headers, whatever the sender's domain.
- **Check:** In a test, a reply from an unlisted domain that references your message stops the sequence.

### L27 · 2026-10-09 · A seed fund reads pre-seed as too early; keep it for the next round
- **Observed:** A fund that invests at seed, after launch and revenue, passed because pre-seed was too early. Of the first five funds to answer, three sent the company to a pitch form, one passed on stage and one misread its location; none spoke about the wording.
- **Rule:** Write only where the fund's own site says it invests at the stage being raised. A pass on stage closes the fund for this round and keeps it for the next, with its stated bar on the record.
- **Check:** Every first email's fund record carries a stage, in the fund's own words, that includes the round being raised.

### L28 · 2026-10-09 · An adviser on the round is not the team
- **Observed:** A proposed deck put a team panel beside the founder, and the standard reply introduced the round's independent adviser with an in-house title. The adviser asked never to be shown as part of the team in external communication.
- **Rule:** Externally, name an adviser as an independent adviser on the round, never on a team slide or with a company title.
- **Check:** The deck and reply builders refuse an adviser's name on a team slide or beside a company title.

### L29 · 2026-10-09 · Hold one copy version long enough to read it
- **Observed:** Nine copy versions went out in four sending days, none to more than 20 people, and no follow-up had gone. When the owners paused to ask what had worked, no wording change could be read.
- **Rule:** Hold one version for a set number of sends (about 40) and read it after the follow-up window before changing the wording. A correction of fact is not a wording change.
- **Check:** The send log shows each copy version's send count and its first and last send dates.

### L30 · 2026-10-14 · A researched fact is not investor relevance
- **Observed:** The owner asked for generic filler to be removed before outreach restarted. The released queue held true but decorative bridges from a partner's career or portfolio into the same product paragraph and an immediate meeting ask.
- **Rule:** A first email records a sourced relevance receipt: the observed fact, why the company fits, the accepted basis and a passed substitution check (the line must fail if another fund's name is swapped in). The opening states the fit plainly, and the first ask is whether the opportunity fits, not for a stranger's time.
- **Check:** The preflight refuses a first email with no relevance receipt.

### L31 · 2026-10-16 · Programme attendance is not investee geography
- **Observed:** An accelerator requires selected teams to spend twelve weeks in one city, but its programme page does not say the company must be incorporated or based there.
- **Rule:** Record a temporary in-person requirement in the geography evidence, but do not treat it as a location restriction unless the fund's own site states one.
- **Check:** A geography stretch on the record cites a stated investee-location rule, not an attendance rule.

### L32 · 2026-10-15 · Read the fund's company-eligibility rule before email 1
- **Observed:** A fund passed after its form because it invests only in companies incorporated in one jurisdiction. Its fit record had already noted a regional focus, and nothing in the process read an incorporation or headquarters rule. A read of every open fund that followed found about half eligible, most of the rest silent, and a few that ruled the company out.
- **Rule:** Before email 1, read the fund's own site for where an investee must be incorporated or based, and record it. A stated rule that excludes the company holds the lead; "not stated" goes ahead with the URL on the record. Re-incorporation is the founder's decision and is never proposed unasked.
- **Check:** Every first email's fund record carries an eligibility reading and its source URL.

### L33 · 2026-10-15 · A new first-email gate can silently hold every follow-up
- **Observed:** A new copy version made the preflight refuse any lead without a sourced relevance record. Leads written before the change had none, so their one follow-up was skipped, neither sent nor stopped, and the dry run reported nothing due.
- **Rule:** After any copy-version or gate change, dry-run the follow-up step and count the skips. Backfill the record for older leads or scope the gate to its own step. Never count follow-ups as moving until the dry run shows them due.
- **Check:** The daily status reports follow-ups skipped by a gate as a number, not as "none due".

### L34 · 2026-10-16 · Review the opener as the assembled email, not as a field
- **Observed:** The opener sits straight before the founder's fixed product line, so openers that said what the company is repeated it. An opener states one sourced fund fact and no verdict about fit. By the third rework round the only acceptable return is fix once or hold.

### L36 · 2026-10-18 · A decline that names other funds is a later-stage watchlist

- **Check:** The closed fund has a trigger recorded, no next follow-up date and no step queued.

# Outreach strategy: gates, the emails, timing and replies

## 1. Gates

Nothing reaches an investor until every gate holds for that lead:

| Gate | Holds when |
|---|---|
| Copy | The copy version in use was approved by the copy owner, with their message reference recorded |
| Release | The release owner released this lead by id, with their message reference |
| Address | Verified, domain agrees with the fund, nobody typed it by hand |
| Minimum | Recorded, and read on the fund's own site for a first email |
| Record | The lead is loaded in the CRM (recording a release does not load it) |
| Hold | No hold reason on the lead |
| Kill switch | Not set |
| Send switches | The instance's live-send flags are on |

A gate that fails skips the lead and leaves it for the next run. It never stops the sequence for good.

## 2. Email 1

Plain words, at most about 90 to 95 words:

1. Subject in plain language. No programme codes or internal labels.
2. The researched opening line.
3. One sentence on what the company is and where it is based. A fund with a geographic mandate will pass on a wrong guess about where you are, and a legal footer is not read. Spell every product name in full; an investor reads an acronym as their own jargon.
4. Traction only as the pinned deck states it. Customers are named only where the deck already names them with their agreement.
5. One line on who the founder is, early. Early-stage investors weigh the founder first.
6. The deck built for this investor, attached.
7. One ask: a short call with the named people, who are copied on the email.

No figure in the body; the deck carries it. Keep every email exactly as sent, attachment included, and log it.

Hold one copy version for a set number of sends (about 40) and read it after the follow-up window before changing the wording. Several versions in a few days leave nothing to read. A correction of fact is not a wording change and goes in at once.

## 3. The round figure in the deck

- Each deck states a round figure matched to the investor: the lowest of the instance's tiers (for example low, mid and high) that covers the fund's minimum.
- State it in the investor's currency where the instance says so (for example euros for European funds). Compare the minimum in that currency as published, not through a rate.
- Use round figures only. A converted figure such as 1.15M reads as a mistake.
- Pin the figure on the fund's record when the first email goes, so a follow-up never changes it mid-thread.
- A minimum above the top tier holds the lead for the owners. A figure above the round ceiling needs the founder.
- Text-check every built PDF: the figure is present wherever the deck states the raise, and no other figure remains.

Attach the PDF. Do not send a hosted link that shows a fixed figure.

## 4. Who sends, and saying an agent wrote it

The sender, signature and copied addresses come from the instance. Never send from a founder's own address, or sign as them, without their explicit word for that sender. Recipients may not realise an AI agent wrote to them. If the instance allows, test a one-line disclosure ("I should mention that I am an AI agent") against no disclosure, fund by fund, and report replies and meetings by half. Answer honestly whenever anyone asks.

## 5. Timing and volume

- Land in the investor's own working morning (for example 07:30 to 11:30 local) on their working days, at least several minutes apart.
- Ramp the daily cap: start around 10 new emails a day and raise it only while bounces stay under 3% and no complaint arrives.
- Two research turns and two sending turns a day suit a raise across regions: research the next region while the last one's mornings run.

## 6. Follow-up

One follow-up, seven business days after email 1, on the same thread, with the deck again (the fund's name on the cover helps). Then stop. More reminders cost goodwill and seldom change the answer.

After any copy-version or gate change, dry-run the follow-up step and count the skips. A gate written for the first email can hold every older lead's follow-up without sending or stopping it.

## 7. Replies

- Treat mail from any address at the fund's domain as a reply, because funds answer from team addresses with the partner copied. A personal mail domain matches only the address you wrote to.
- Funds also answer from a second company domain, sometimes through an email assistant. Record every domain a fund's people mail from, and also match on your own Message-ID in the reply's References or In-Reply-To headers, whatever the sender's domain.
- Stop every sequence at that fund. Colleagues not yet written to are held.
- Within the hour, send the standard answer the owners approved: introduce the people who take meetings, propose a call and give the booking link. Once per thread, never to an opt-out, a decline or an automatic reply, and not after an owner has answered.
- Follow the thread until a call is on the calendar: one reminder seven business days after the standard answer, never before the investor's own stated timeline.
- A decline can arrive outside your thread, from a form system to a founder's own address. Close it by hand when it is forwarded; automation will not see it.
- Count replies from the sequence record, not from mailbox search: a reply moved to trash disappears from search.
- A fund that names a condition (a first paid pilot, live deployments) gets that condition recorded as a re-entry trigger, not a follow-up date. Customer news that meets it goes to the founder the same day.
- When the founder takes a fund over after a meeting, stop the sequence for every person there between scheduled runs, then read the stops back after the next run. A scheduled job that rewrites the sequence file can undo a hand edit.

## 8. Two decks

Keep the short teaser for first emails. Pitch forms and first calls get a fuller deck in the order funds expect: founders first, problem, product, traction by stage, market, competition by category (without naming rivals if the owners rule that out), business model, go-to-market, roadmap, and the ask with its use of funds. Before a fuller deck goes to any fund, get a friendly read from two or three angels or an accelerator.

An adviser on the round is named externally as an independent adviser, never on a team slide or with a company title. Ask anyone named in a deck or reply how they want to appear before it goes out.

## 9. Compliance

Every email carries the legal entity and registered office, a line saying it is meant for investment professionals, and a working opt-out. An opt-out is permanent and checked again just before each send. Keep the processing basis, retention and jurisdiction on each record from the instance's policy, never self-assigned.

## 10. Daily status

The owners usually want one short daily figure: people and funds written to, funds that replied, funds that declined, meetings booked, what went today and what is coming. Count by fund and say how each figure is counted.

## 11. Pausing the lane

A pause reaches every path that touches the lane: the senders, the follow-up and research steps, any task dispatcher or scheduled carrier that files lane work, and the daily status. Dry-run each one with the kill switch set and record what it printed. Unless the owner asks to keep the status going, it pauses with the lane. Before the pause is lifted, check that every fund an owner took over is stopped, and re-run by hand any research turn that was skipped.

# Research: funds, people, minimums and addresses

Research is judgement work. Run it as a turn (for example one turn for each time-zone block of investors you write to), and end each turn with one release list.

## 1. Lanes

Rank lanes by thesis fit with the round, then by cheque fit:

| Lane | Who | Watch for |
|---|---|---|
| Sector specialists | Funds and corporate venture arms that invest in the company's industry | A portfolio company that competes with you |
| Regional early-stage | Pre-seed and seed funds where the first customers are | A fund that reads you as belonging to another region |
| Technology-first | Funds with a thesis on the company's core technology | Minimum cheques above the round |
| Angel networks and syndicates | Groups with a published submission route | Fees to pitch are spend, and need the owner |
| Corporate venture | Venture arms of companies in the sector | A parent that is a customer, a prospect or a competitor |

Exclusions, checked before release: a fund backing a direct competitor (the owner decides each case); any organisation on the company's customer or prospect lists unless an owner says otherwise; anyone who opted out; any person whose current employer you cannot confirm.

Stage, checked on the fund's own site: write only where the fund says it invests at the stage being raised. A seed fund with one earlier deal in its portfolio is not an earlier-stage fund. A fund that passes on stage is closed for this round and kept for the next, with its stated bar (for example revenue) on its record.

## 2. The fund record

Read the fund's own website first, then press quoting the fund or its partners. A tracker or aggregator figure on its own is not the fund saying it: put it in a note and leave the value empty.

Record for each fund:

- name, website domain and any other domain its people use for email;
- investor type, region and the city its team is based in;
- thesis and stage in the fund's own words, with the page each came from;
- minimum cheque (section 3), with source and note;
- portfolio companies that compete with the company raising (section 4);
- its pitch form or submission route, if it has one (section 5).
- where an investee must be incorporated or based, read on the fund's own site, with the URL; a temporary programme attendance requirement is recorded but is not a location rule. A stated rule that excludes the company holds the lead before email 1.

## 3. Minimum cheque

1. The minimum is the lowest cheque the fund says it writes: the bottom of its first-cheque range, or its single stated cheque.
2. "Up to X", an average cheque or the size of a round the fund led are not minimums. Note them; leave the minimum empty.
3. Record the amount and currency exactly as published, plus a converted value in the instance's base currency at a named reference rate on the research date.
4. Before a first email the minimum, or the fact that the fund publishes none, must be read on the fund's own site. A press figure may set the deck only with an owner's named exception on the record.
5. Note the average cheque and whether the fund likes to lead. A fund whose average is many times its minimum may read a small round as below its usual cheque; the owners decide whether to match the average instead.

## 4. Competitor check

Search each fund's portfolio for companies that compete with the one raising. Keep a running list of competitors and their known backers in the instance. A match puts a hold reason on the lead and goes to the owner; it is never silently dropped and never silently sent. Peers in the same sector that do not compete are not conflicts, but a fund that already knows the market may want a different framing.

## 5. Pitch forms

Many funds route every cold approach, social messages included, through a form they review weekly. Find the form during research. A fund with a form goes on the release list as a form submission: draft the answers from the approved deck for a named owner to submit, with the full deck if the form asks for one. Do not also send the cold email unless the owners say so.

## 6. People at each fund

Take the top three to five decision makers from the fund's own team page, partners first. Each is a lead of its own, with its own opening line and the profile URL from that page. Once anyone at the fund replies or opts out, nobody else there is written to.

## 7. Addresses

- Use only an address observed on a source or returned by a verification provider. Never build an address from a name pattern and probe it.
- Before a paid reveal, list every domain the fund's people use. A domain that redirects to the fund's own site and has mail records counts as the fund's. A verdict computed before the domain was listed will not update itself, and a second reveal costs again.
- A mailbox reported valid is not proof of the employer. Require the address domain to agree with the fund. Partners often come back at a portfolio company, a university or a side role.
- When a reveal returns the wrong employer, try the fund's next named partner rather than the same person again. When a reveal misses, re-key it on the profile URL from the fund's own team page before giving up. A miss usually costs nothing.
- Put every failed lead on hold with its reason straight away, so a later enrichment run does not bill it again.

## 8. Opening lines

One plain fact about the fund or person, from its own thesis or portfolio, said the way a person would say it across a table. Then stop. Count the patterns across a batch: if one construction opens more than about one line in ten, it reads as a template and should be retired. Never invent familiarity, praise or urgency.

Review each opener in the email as the sending script renders it, read aloud with the line that follows, and read the openers for partners at one fund side by side. An opener carries no verdict about fit ("the relevant fit here"), does not describe the fund's own portfolio company back to it, and does not tell the fund its own ticket range.

## 9. Angels

Angel networks and platforms are researched like funds, through their own submission route. Individuals are researched only where they say publicly that they invest as angels, never from broad lists, and kept in a separate record. Before writing to any private individual, someone qualified must clear the financial promotion rules for that person's jurisdiction. Until then, research only.

## 10. End of turn

Write each lead to the database and the CRM, pacing CRM writes under its rate limit and reading back that every record and its first activity exist. Then build the release list (SKILL.md, step 4).

# Weekly refresh: keep the database, the learnings and this skill current

Run once a week, on a fixed day, as one task with one owner. It takes under an hour when the daily records are kept.

## 1. Rebuild the database

Rebuild the investor database from the outreach records and the CRM (see [database](#file-references-database-md)). Write its stats file. Compare with last week: new funds, new people, first emails, follow-ups, replies, declines, meetings.

## 2. Read the week

Read every reply, decline, bounce, opt-out and owner instruction from the week, and the daily status reports. For each, ask: did it change, or should it change, how we research, write, time, follow up or count? A pass with no reason teaches nothing on its own; a fund's published guide, a reason given in a reply or an owner's correction usually does.

## 3. Write the learnings

Add each lesson to the instance log with the next number, the date it was learned, what was observed, the rule it produced, the evidence (message references, record ids) and whether it is safe to publish without names. A lesson becomes a rule only when the rule is also in the instance's procedure and, where it can be, in the send code. Retire a lesson that a later one replaced, and say which.

## 4. Feed the memory store

Ingest the refreshed instance skill, the learning log and the week's reports into the team's memory store, then prove retrieval: search for two of this week's lessons by phrase and by meaning, and check that the store's graph links them to the funds and rules they mention. If vector or graph search returns nothing new, the store is not learning. Report it to the owner with the evidence rather than assuming it worked.

## 5. Publish the generic edition

1. Copy every lesson marked safe to publish into the generic learnings, rewritten without names, figures that identify the raise, message references, addresses or dates that point at a person.
2. Run the publishing check: search the generic files for the instance's investor names, fund domains, people, email addresses, internal paths, message references and round figures. Any hit blocks publication.
3. Bump the skill version (patch for new lessons, minor for a changed procedure), render the single-file edition, run the repository's validation, security scan and tests, and open or update one pull request. Merging is the repository maintainer's decision.

## 6. Report

One short note to the owners: the week's numbers by fund, the new lessons in a sentence each, whether the memory store took them, and the pull request. Nothing is sent to investors as part of this task.
