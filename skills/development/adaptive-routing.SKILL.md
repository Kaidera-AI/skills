# Adaptive routing in OpenKai

Work in the customer's standalone OpenKai environment. Resolve paths from its installed configuration and the active workspace; KOS and Cortex are not prerequisites. Select a mode from the requested outcome and load only its reference.

## Discovery

Inspect the installed version, the native versioned catalogue reader and its compatibility receipt before selecting settings. Use that one provider/model authority for provider-qualified identities, availability and supported controls. Preserve the customer's constraints on cost, quota, input and task quality.

If the catalogue is unavailable, return WAIT and select no model.

Unknown versions, missing capability metadata or missing native controls remain explicit WAIT/refusal. Source code or a model name does not establish installed capability. This skill ships guidance, not a replacement catalogue, reader, configuration writer, timer or decision engine.

## Choose the mode

- **Shift:** read [Shift](#file-references-shift-md) for postures, supported lanes, pins and bounded fallback.
- **Fusion:** read [Fusion](#file-references-fusion-md) for explicit cast selection and the extra work/cost.
- **Run Profile or effect investigation:** read [Run Profiles](#file-references-run-profile-md) for native schema, refusal, attribution, effect and expiry.

A request to plan is complete with supported choices or named WAIT inputs. It does not authorize changing configuration or starting a model run. For authorized action, use the installed product's supported mutation surface and keep unrelated settings intact. An unfamiliar setting name is not permission to try a guessed flag.

## Current dependency boundary

Runnable catalogue/native examples require the versioned catalogue reader, installed-version compatibility, configuration controls and native profile/effect contracts from the product. Until those receipts exist, produce a conceptual plan and the exact missing prerequisite. No runnable catalogue/profile template is included here. A same-named skill in a marketplace or a successful static check proves neither those native features nor account access.

## Return evidence

Report the mode, constraints, catalogue/native versions and supported selection or refusal. Separate configured, requested, resolved/fallback and served settings. State actual changes and their scope; attach the bounded native effect/expiry receipts where available. Missing proof remains UNVERIFIED. Recovery uses current native state and preserves concurrent changes.

## Bundled file: references/fusion.md

# Fusion

Use Fusion when independent construction and synthesis can improve a difficult task enough to justify the extra work. A simpler single run can satisfy a task that does not benefit from the extra work. Decide within the customer's existing purpose and cost/call budget.

## Cast selection

Resolve architect, builder and any judge through the native catalogue before execution, with explicit nonempty provider-qualified identities. Preserve the customer's specified cast. A deliberately same-model pair requires an explicit choice and cannot be described as model diversity.

An unresolved builder requires refusal, not reuse of the current or architect model.

Native defaults or historical source fallbacks are not evidence of a valid chosen cast. If the installed contract cannot express or verify the requested cast, return the unsupported requirement instead of inventing a setting.

## Budget and call plan

State which extra work the proposed cast performs and account for the additional builder, judge and synthesis calls permitted by the native workflow. Include native availability/quota and the customer's budget. Unknown cost or authorization does not mean unlimited calls.

An extra call outside the approved purpose or budget requires refusal before dispatch.

## Effect and learning

Report the identities that actually built and combined the result, the evidence for agreement/disagreement, discarded alternatives and remaining uncertainty. Native learning or bandit adaptation is a separate capability: require its owner/effect receipt before claiming it works. A record of a proposed cast is not evidence of its execution or learning.

# Native Run Profiles

Use the installed OpenKai contract to prepare a bounded, attributed selection for the actual local agent/task. Catalogue identity, native schema and native controls are prerequisites; this reference does not define a replacement JSON schema or command API.

## Compatibility

Read the accepted native schema/reader and installed-version compatibility, including the supported provider, model, harness and controls. Use only native field names and values returned by those contracts. No runnable example is provided until those contracts are available.

For unknown schema or installed-version compatibility, return WAIT before any write or run.

## Unsupported controls

Check requested effort and fast mode against both the catalogue and the installed harness surface. Missing metadata is unknown support, not an inferred family feature. Preserve the customer's requested constraints rather than quietly changing them.

Refuse requested unsupported fast mode before writing or dispatching; preserve the requested controls.

## Attribution and window

Prepare the native agent/harness, provider/model, supported effort/fast choice, Fusion cast and Shift bounds with a reason and attributed decision evidence. Use a bounded native time/task window. Applying a profile uses the product-owned writer/lifecycle; the skill supplies no independent expiry daemon or profile database.

## Effect proof

Compare requested settings, resolution/fallback and actual served evidence for the same run/profile/catalogue/native version. Confirm every requested effect the product can report. A changed configuration, argv, status label or source implementation is a declaration until that evidence exists.

A request echo is not served effect; missing correlated evidence remains UNVERIFIED.

## Expiry

Use the native lifecycle to remove the matching expired profile. Inspect the current base and newer overlapping profile before concluding what applies. Recover only the affected setting through its supported native operation and record the effect.

Expiry exposes the current base; never replace a newer base with a captured old snapshot.

A missing native lifecycle or correlated expiry receipt is a WAIT/unverified outcome. A static instruction test or simulated receipt cannot qualify actual customer/native behavior.

## Bundled file: references/shift.md

# Shift

Use Shift for routing within the supported task/session scope. Match quality, balanced or saver posture to the customer's quality requirement and bounded cost/quota policy. Resolve every lane from the native catalogue; a tier label is not a model identity.

## Bounds and selection

Choose an efficient/capable lane only when the installed version exposes it. Apply supported floor, ceiling and never pins to provider-qualified identities. Keep required input/tool capabilities and the customer's explicit choice. A fallback must remain inside those bounds and be reported, including the actual provider route.

Source or historical notes about session routing do not establish per-agent/subagent support. Use only the installed scope and effect contract. An unavailable acceptable route is a refusal, not permission to use an unrelated current/default model.

## Configuration and proof

Use the native configuration surface confirmed by the installed version. OpenKai's own settings slice and upstream settings CLI may be separate stores; do not infer that a similarly named CLI key writes the routing slice. Preserve unrelated fields and concurrent updates. Corrupt or silently empty configuration is not a successful readiness test.

Collect the native decision and served-effect evidence for the bounded run. A selected tier, changed config or status badge alone does not show which model ran. Report the distinction and keep unobserved behavior UNVERIFIED.
