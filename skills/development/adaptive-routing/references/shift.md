# Shift

Use Shift for routing within the supported task/session scope. Match quality, balanced or saver posture to the customer's quality requirement and bounded cost/quota policy. Resolve every lane from the native catalogue; a tier label is not a model identity.

## Bounds and selection

Choose an efficient/capable lane only when the installed version exposes it. Apply supported floor, ceiling and never pins to provider-qualified identities. Keep required input/tool capabilities and the customer's explicit choice. A fallback must remain inside those bounds and be reported, including the actual provider route.

Source or historical notes about session routing do not establish per-agent/subagent support. Use only the installed scope and effect contract. An unavailable acceptable route is a refusal, not permission to use an unrelated current/default model.

## Configuration and proof

Use the native configuration surface confirmed by the installed version. OpenKai's own settings slice and upstream settings CLI may be separate stores; do not infer that a similarly named CLI key writes the routing slice. Preserve unrelated fields and concurrent updates. Corrupt or silently empty configuration is not a successful readiness test.

Collect the native decision and served-effect evidence for the bounded run. A selected tier, changed config or status badge alone does not show which model ran. Report the distinction and keep unobserved behavior UNVERIFIED.
