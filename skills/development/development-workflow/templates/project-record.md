# Project configuration record

Record these values in the project's existing configuration system; this file is a
template, not a second mandatory database.

- Project identity and project type: development / non-development.
- Repository operations: on / off; decision source and explicit overrides.
- Lifecycle owner and pinned skill version/source digest.
- Human decision owner; programme/product lead; implementers; independent reviewer;
  human file reviewer; QA owner when required; operator/service owner; records owner.
- Accepted plan and policy locations; task/change/review/incident systems of record.
- Workspace, data boundaries and permitted tools; source/model data destinations.
- For AI: operator-selected model/provider/effort, approved fallbacks, time/token/cost
  ceilings and retries. For humans: due policy; no synthetic model requirement.
- Risk classes and required verification/QA; review-round limit and escalation.
- Reserved actions, approver identity, scope/expiry of standing authority.
- Services/environments, support route, monitoring and recovery owners.
- Review-tool decision record and current state.
- Host binding and enforcement evidence, or NOT QUALIFIED with missing proof.

Do not fill unknown authority or capability fields by guessing. Resolve only the
missing field before its dependent operation. Unrelated authorized planning can continue.
