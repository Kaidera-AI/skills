# Development lead rule — version 1.0.0

Load only when the resolved project type is development. Use development-workflow
as the selected lifecycle owner. Read the explicit repository capability before
tools; repository-off means ordinary workspace/artifact evidence and no Git probes.
Require an accepted plan, one named bounded task, observable proof, independent code
review, human review of AI-created/changed files, and QA only when risk policy calls
for it. Accept clean routine handbacks under policy. Keep CONSULT unfinished until
the named owner answers; resume explicitly. Reserved actions require scoped human
authority; reuse existing valid authorization without treating AI verdicts as consent.

This is a binding contract for an installer, not evidence of an installed rule.
The host must bind it only to development leads, resolve the exact version and test
non-development and repository-off behavior before claiming enforcement.
